# NidoOS Engineering Incident Ledger

Concise record of hard-won Ubuntu 26.04 (`resolute`), `arm64`, and GNOME integration failures resolved in NidoOS, paired with the automated gates preventing regression.

| ID | Failure Mode | Root Cause | Permanent Fix | Automated Regression Gate |
| --- | --- | --- | --- | --- |
| `INC-001` | Subiquity install aborts with `NO_PUBKEY` / `file:/cdrom resolute Release is not signed` | Ubuntu 26.04 stores its per-ISO ephemeral Ed25519 signing key inline inside `/etc/apt/sources.list.d/cdrom.sources`. Deleting `*cdrom*` during chroot build removed that key before repack. | Stash `*cdrom*` outside chroot in `customize.sh`, restore before repack, and remove only after real disk install via `native-first-cleanup`. | `iso-builder/scripts/verify_cdrom_signature.py` + offline chroot `apt-get update` against ro-mounted `/cdrom` (`APT::Update::Error-Mode=any`) + `tests/verify_repo.sh` Gate 6. |
| `INC-002` | Vietnamese monospace tofu (`đọc`, `thể`, `kiểm`) in Subiquity log & terminal | Ubuntu 26.04's variable `UbuntuMono[wght].ttf` and `NotoMono-Regular.ttf` lack key Vietnamese diacritic/precomposed codepoints (`U+0309`, `U+0323`, `U+1EC3`, `U+1ECD`). | Reject `/usr/share/fonts/truetype/ubuntu/*` in `52-ubuntu-nido-vietnamese.conf`, alias `Ubuntu Mono` & `Noto Mono` to `Liberation Mono`, and bind-mount `LiberationMono-Regular.ttf` into the Live Installer Snap (`bind-installer-fonts`). | `fc-match` + OpenType `cmap` audit in `customize.sh` + `bind-installer-fonts --self-test --verify-system`. |
| `INC-003` | `GDBus.Error:org.freedesktop.systemd1.UnitMasked: Unit packagekit.service is masked` during `apt-get update` | Masking `packagekit.service` while leaving `/etc/apt/apt.conf.d/20packagekit` and `org.freedesktop.PackageKit.service` active caused every APT refresh (including Subiquity) to fail D-Bus activation. | `dpkg-divert` both files in `0110-nido-minimal-prune.hook.chroot` and `nido-desktop-settings/DEBIAN/postinst`. | Chroot absence assertions (`test ! -e`) + `UnitMasked` grep guard on offline chroot `apt-get update` output in `customize.sh`. |
| `INC-004` | `arm64` APT mirror breakage & unsupported `x86_64`-only apps shown in NidoHub on `aarch64` | Rewriting `ports.ubuntu.com` broke `arm64` chroots; displaying `x86_64`-only catalog/Flathub apps on `arm64` produced broken install buttons. | Limit `mirror.bizflycloud.vn` rewrite strictly to `amd64`; hide unsupported host architectures by default (`hide_unsupported=True`) in `app_store.py`, `catalog.json`, and `app.py`. | `packages/nido-hub/files/usr/lib/nido-hub/self_test.py` (`arm64` vs `amd64` catalog & Flathub search tests) + `tests/verify_repo.sh`. |
| `INC-005` | Sluggish Live ISO & low-RAM VM responsiveness compared to stock Ubuntu | Background indexers (`localsearch-3`), update notifiers, desktop icon extensions, and cold-starting AI onboarding on Live ISO consumed CPU/RAM. | Prune unnecessary autostart/user services in `0110-nido-minimal-prune.hook.chroot`, enable `systemd-zram-generator` + `earlyoom`, and suppress AI onboarding on Live ISO sessions. | Masked-unit & autostart absence checks in `customize.sh` + `dpkg -s earlyoom systemd-zram-generator`. |
| `INC-006` | Stale `dpkg/status` & monolithic caches overriding customized base layer in Ubuntu 24.04/26.04 layered Casper ISOs | Repacking `minimal.squashfs` without reconciling `minimal.standard.live.squashfs` left older `dpkg/status`, `ld.so.cache`, `gschemas.compiled`, and fontconfig caches on top. | Reconcile `live_delta` against base rootfs via `reconcile_live_layer.py` and refresh `install-sources.yaml` via `update_install_sources.py`. | Unit tests for `reconcile_live_layer.py` and `update_install_sources.py` (24.04 & 26.04) in `tests/verify_repo.sh` Gate 6. |
| `INC-007` | Fresh installs hide `ubuntu-apt` apps (`vlc`, `gimp`, `obs-studio`) in NidoHub & fail `nido-hub --self-test` before first `apt update` | `probe_apt_candidate_available()` treated missing `apt-cache policy` candidates on an empty `/var/lib/apt/lists` as `False` ("unsupported arch") instead of `None` ("unsynced cache"). | Check `has_populated_apt_lists(source)` before returning `False` in `app_store.py`; inject mock APT prober in `self_test.py`; run `nido-native-first-cleanup.service` as non-blocking `Type=simple`. | Empty vs populated APT lists tests in `self_test.py` + `nido-doctor` health CLI + `tests/verify_repo.sh`. |
| `INC-008` | GTK 4.22 apps consume 330–538 MB RSS each on VM virtual GPUs (`vmwgfx`) + `20packagekit.nido-disabled` triggers APT `Notice:` | GTK 4 defaults to Vulkan/GL software shaders (Mesa lavapipe/llvmpipe) per process on virtual GPUs; diverting `20packagekit` inside `/etc/apt/apt.conf.d/` left an invalid-extension file. | Add dynamic `60-nido-vm-gsk` systemd user-environment-generator setting `GSK_RENDERER=cairo` only on VMs with virtual GPUs (cuts `nido-hub` 538→133 MB); relocate `20packagekit` divert to `/var/lib/ubuntu-nido/disabled/20packagekit`. | `60-nido-vm-gsk --self-test` + `nido-doctor` + `customize.sh` + `tests/verify_repo.sh` Gate 5. |
| `INC-009` | NidoOffice Linux Gateway SSO races on boot, fails after AI OFF→ON or with non-`nido` primary backend, and VM RTC drift breaks `apt update` | `nidoai-gateway` started before D-Bus/GNOME Keyring unlocked and cached empty tokens without hot-reloading; `login_nido_account`/`register_nido_account` did not flip `NIDOAI_ENABLED=0→1` or re-enable the user unit; `nido-llama` routed to `primaryBackend` (404 on Gemini/OpenAI); fresh VMs drifted behind APT `InRelease` Date. | Order `nidoai-gateway.service` after D-Bus/Keyring + resolve `/run/user/$UID/bus` in `secret-store.js`; hot-reload config on mtime/Keyring unlock & route `nido-llama` to `nido` in `server.js`; wake gateway in `nidooffice-desktop` launcher; flip `NIDOAI_ENABLED=1` & `enable` unit in `nido-hub`; enable NTP in `native-first-cleanup` and add Clock/SSO/Office/Disk checks to `nido-doctor`. | `nido-hub --self-test` + `nido-doctor --self-test` + live Gateway hot-reload & `nido-llama` routing E2E in `tests/verify_repo.sh` Gate 5. |
